=== 케이스 2. 멀티 서버 작업 스케줄러 (마감 빠른 순) ===
  제출: A 4건, B 3건
  A 실행          → 일일 리포트(09:30)
  긴급 처리        : 알림 메일 마감 12:00 → 09:40  (decreaseKey)
  마감 연기        : DB 백업 10:00 → 14:00  (delete + 재삽입)
  취소            : 로그 정리  (delete)
  server-A 장애 → 대기열을 server-B 로 이관 (meld O(1)), 이제 B 5건
  DB 백업 의 현재 서버: server-B
  B 실행 순서      → 알림 메일(09:40), 결제 정산(09:45), 캐시 갱신(10:15), 이미지 변환(13:00), DB 백업(14:00)
  취소된 작업 긴급 처리 시도 → 거부: 로그 정리 는 대기 중이 아닙니다 (CANCELLED)
  실행 끝난 작업 취소 시도   → 거부: 이미지 변환 는 대기 중이 아닙니다 (DONE)
